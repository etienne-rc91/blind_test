# Musique pilotée par l’app — plan de construction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** les manches buzzer peuvent contenir des morceaux (fichiers de `musiques/` ou titres Spotify) que la Régie joue elle-même : passage début/fin, pause au buzz, reprise sur M, son de victoire sur B, Rejouer l’extrait (R), révélation sur le Grand écran ; préparation dans Création avec une barre de temps à deux poignées.

**Architecture :** le serveur (`lib/game.js`) décide de l’état de la musique (`song` : morceau courant, `audio`, `seq`, `outcome`) et calcule `audible` ; la Régie ne fait qu’appliquer cet état à un lecteur. Un lecteur commun (`public/players.js`) cache la source (`file` → `<audio>`, `spotify` → Web Playback SDK). Le format CSV gagne trois colonnes en fin de ligne ; les anciens fichiers restent valides. Spotify (OAuth PKCE, jetons, recherche, pochettes) vit dans `lib/spotify.js`, sans dépendance npm.

**Tech stack :** Node ≥ 18 (`fetch`, `crypto` natifs), Express 4.21.2, socket.io 4.8.1, `node:test` + `node:assert/strict`. Spotify Web API + Web Playback SDK (`https://sdk.scdn.co/spotify-player.js`).

**Spec :** `docs/superpowers/specs/2026-10-28-musique-design.md` (à lire en entier avant de commencer). Vocabulaire : `CLAUDE.md`.

## Global Constraints

- Internet **uniquement** pour les morceaux Spotify. Une partie sans morceau Spotify ne charge rien de distant (le SDK n’est injecté que si la manche courante contient un morceau `spotify`) ; une panne Spotify ne bloque jamais buzzers, points ni Z.
- Aucune nouvelle dépendance npm. Pas de build. JS vanilla.
- Le serveur est l’unique source de vérité : la Régie ne décide jamais de mettre en pause ou de relancer, elle applique `state.song.audible`. Seul fait remonté par la Régie : la fin du passage (`host:ended`).
- `performance.now()` reste la première instruction du handler `buzz` ; rien n’est ajouté avant.
- Toute action animateur passe par `game.host()` (annulable). `host:ended` n’est **pas** une action annulable.
- Un Z ne rend jamais la musique audible si elle ne l’était pas juste avant le Z.
- Ni le Buzzer ni le Grand écran (avant révélation) ne reçoivent réponse, nom de fichier ou identifiant Spotify.
- Interface, README, commentaires en français (apostrophe `’`, espace avant `:` `?` `!`). Identifiants en anglais. Commits en anglais, Conventional Commits, un changement logique par commit, terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Noms : un morceau d’une manche est un `song` (`section.songs`) ; `round` reste le compteur des manches libres ; `phase` reste réservé aux buzzers.
- Formats audio acceptés : `mp3 m4a aac ogg oga wav flac`, 50 Mo maximum. Temps en secondes entières, écrits `m:ss`.
- `exemple-soiree.csv` a des modifications locales de l’animateur : ne pas le toucher, ne pas le commiter.

**Écart assumé à `CLAUDE.md` §5 (« un seul fichier HTML par écran, JS inline »)** : le lecteur commun est dans `public/players.js`, partagé par la Régie et Création, pour ne pas dupliquer la couche Spotify. À signaler à l’animateur en fin de Tâche 6.

### Tâche 3 : état de la musique dans le jeu

**Files :** Modify `lib/game.js`, `lib/game.test.js`

**Interfaces :**
- Consumes : `isSong` (Tâche 1), manches avec `songs` (Tâche 2).
- Produces :
  - `createGame({ ..., coverOf = () => null })` : `coverOf(song) -> string|null` (URL de pochette, fournie par le serveur).
  - État interne : `song = { index: number|null, concluded: boolean, outcome: null|'found'|'closed', audio: 'stopped'|'playing'|'paused'|'ended', seq: number }` et `endedSeq` (dernier `seq` dont la fin a été atteinte, hors annulation). `hasSongs()` = manche courante buzzer avec `songs.length > 0`. `audible = audio === 'playing' && phase !== 'buzzed'`.
  - L’avancement d’une manche avec morceaux réutilise `progress[i].index` = nombre de morceaux lancés.
  - Transitions (manche avec morceaux uniquement ; manches libres et QCM inchangées) :

    | Action | Condition | Effet |
    |---|---|---|
    | `open` (Espace) | `index === null` ou `concluded` | s’il reste un morceau : `index = progress.index`, `progress.index++`, `concluded=false`, `outcome=null`, `audio='playing'`, `seq++`, `openRound({newSong:true})` ; sinon rien |
    | `open` | non conclu, `audio==='paused'`, `phase!=='buzzed'` | `audio='playing'` |
    | `open` | autre cas | rien (`changed:false`) |
    | buzz | — | inchangé (la pause découle de `phase==='buzzed'`) |
    | `correct` (B) | `phase==='buzzed'` | comme aujourd’hui + `concluded=true`, `outcome='found'`, `audio='stopped'` |
    | `wrong` (M) | `phase==='buzzed'` | inchangé ; `audio` intact (reprend si `playing`, reste muet si `ended`) |
    | `close` (F) | morceau en cours non conclu | comme aujourd’hui + `concluded=true`, `outcome='closed'`, `audio='stopped'` |
    | `replay` (R) | `index !== null` et `phase!=='buzzed'` | `audio='playing'`, `seq++` |
    | `songEnded(seq)` (non annulable) | `audio==='playing'` et `seq===song.seq` | `audio='ended'`, `endedSeq=seq` ; renvoie `true` si changé |

  - `snapshot()` / `restore()` incluent `song` **sauf `seq`** (compteur qui ne recule jamais : la Régie repart de Début quand `index` ou `seq` change). Après `restore`, si `audible` est devenu vrai alors qu’il était faux avant le Z : `audio = (endedSeq === song.seq ? 'ended' : 'paused')`.
  - `section`, `reset-scores`, `import`, `newEvening`, `load` remettent `song` à `{index:null, concluded:false, outcome:null, audio:'stopped'}`.
  - `isSection` : manche buzzer valide si `songs` absent (= `[]`) ou tableau de `isSong`. `load` borne `progress[i].index` par `songs.length` pour une manche buzzer.
  - `publicState` : `sections[]` gagne `songCount` et `spotifyCount` ; nouveau champ `song` :
    - `null` si `!hasSongs()` ;
    - `host` : `{ index, total, played: progress.index, concluded, outcome, audio, seq, audible, songs: [...] }` (morceaux complets) ;
    - `screen` : `{ number: index===null ? null : index+1, total, playing: index!==null && !concluded, reveal: concluded ? { answer, cover: song.source==='spotify' ? coverOf(cur) : null } : null }` ;
    - `player` : `null`.
  - `game.songEnded(seq: number) -> boolean` exporté ; nouvelle action `host('replay')`.

- [ ] **Step 1 : tests** (helper `withSongs(n)` qui importe une manche buzzer de n morceaux fichiers) :
  - `space starts the first song and buzz makes it inaudible` : `open` → `song.index===0`, `audible===true` ; buzz → `audible===false`, `audio==='playing'`.
  - `space is ignored until the song is concluded` : `open`, `open` → `changed:false`, `index===0`, `played===1`.
  - `wrong resumes, correct concludes with found` : buzz, `wrong` → `audible`; buzz, `correct` → `concluded`, `outcome==='found'`, `audio==='stopped'`.
  - `close concludes with closed and space moves on` : `close` → `outcome==='closed'` ; `open` → `index===1`.
  - `space after the last song does nothing`.
  - `replay restarts from start, not while buzzed` : `seq` augmente ; après un buzz non jugé, `replay` → `changed:false` ; après `correct`, `replay` → `audible`, `concluded` reste vrai.
  - `stale ended is ignored` : `open` (seq s), `replay` (s+1), `songEnded(s)` → `false`, `audio==='playing'` ; `songEnded(s+1)` → `true`, `audio==='ended'`.
  - `wrong after the passage ended stays silent` : `songEnded`, buzz, `wrong` → `audible===false`.
  - `undo never makes music audible` : `open`, `score +1`, `songEnded(seq)`, `undo()` → `audio==='ended'`, `audible===false`. Et : `open`, `close`, `undo()` → `audio==='paused'`, puis `open` → `audible`.

### Tâche 6 : Régie — jouer les morceaux fichiers

**Files :** Create `public/players.js` ; Modify `public/host.html`, `server.js` (servir `players.js` : déjà couvert par `express.static`)

**Interfaces :**
- Consumes : `state.song` (rôle host, Tâche 3), événements `sound`, `host:ended`, `host:replay` (Tâche 5).
- Produces (`public/players.js`, script classique qui définit `window.Players`) :
  ```
  Players.create(source: 'file'|'spotify', opts) -> Player
  Player.load(song) -> Promise<void>        // prépare la source (fichier : /musiques/<ref>)
  Player.seek(sec) / play() / pause() -> Promise<void>
  Player.position() -> Promise<number>      // secondes
  Player.duration() -> Promise<number|null>
  Player.onError(fn(message))
  ```
  `file` : un élément `<audio preload="auto">`. `spotify` : ajouté en Tâche 10 (lève `Spotify non disponible` d’ici là).
- Contrôleur dans `host.html` : `applySong(song, mine)` :
  - pas propriétaire du son (`mine===false`) → tout lecteur en pause, rien d’autre ;
  - clé `${index}:${seq}` changée → `load` puis `seek(start)` ;
  - puis `audible ? play() : pause()` ;
  - pendant la lecture, toutes les 200 ms : `position() >= end` → `pause()` et `emit('host:ended', { seq })` (une fois par `seq`) ; une fin réelle du fichier vaut fin de passage ;
  - `outcome` passe à `'found'` pour une nouvelle clé `${index}:${seq}:found` → `fanfare()` (WebAudio, 3–4 notes, ≤ 1,2 s, comme `beep()`). Pas de fanfare dans une manche libre ;
  - erreur de lecture → texte `Lecture impossible : <message>` dans le bloc, jeu inchangé.
- Interface (maquette validée `.superpowers/brainstorm/…/regie-morceau.html`) : bloc central quand `state.song` : réponse en gros, `Morceau i / n · 📁` ou `· ♪ Spotify`, barre d’avancement du passage + état (`Lecture`, `En pause (buzz)`, `En pause`, `Passage terminé`, `Conclu`), liste des morceaux (✓ joués, ▶ en cours, à venir) ; bouton `Rejouer l’extrait` `<kbd>R</kbd>` ; si `index===null` après le dernier : `Manche terminée — Suivante ▶`. Bouton `Le son sort ici` visible quand `mine===false`. Touche `r` → `host:replay` (ignorée en QCM et dans les champs). Le libellé de Espace devient `Morceau suivant` / `Reprendre` selon l’état.
