# Vidéos dans les manches buzzer et QCM — plan de construction

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un morceau de manche buzzer, ou l’extrait d’une question QCM, peut être une vidéo (fichier de `videos/` ou YouTube), lue et affichée par le Grand écran du PC de la Régie, avec le déroulé habituel (Espace / buzz / M / B / F / R / Z, ou Entrée en QCM).

**Architecture :** deux sources de plus (`video`, `youtube`) dans `lib/songs.js`, donc dans le CSV, les parties et `isExtract`. L’état `song` de `lib/game.js` ne change pas : pour un passage vidéo, c’est le **Grand écran qui lit** (un seul : le dernier ouvert depuis le PC du serveur) qui applique `audible` et remonte `screen:ended` ; la Régie n’ouvre aucun lecteur, elle reçoit la position et les erreurs relayées par le serveur. Les règles d’affichage (vidéo visible seulement pendant la lecture, sinon bandeau / révélation / cache) et les avertissements de la Régie sont des fonctions pures dans `public/video-view.js`, testées sous Node.

**Tech stack :** Node ≥ 22.9, Express 4.21.2, socket.io 4.8.1, `node:test` + `node:assert/strict`, `public/players.js`, API IFrame YouTube (chargée seulement pour un morceau YouTube), oEmbed public YouTube (sans clé).

**Spec :** `docs/superpowers/specs/2026-10-28-video-design.md` (à lire en entier). S’appuie sur `2026-10-28-musique-design.md` et `2026-10-28-qcm-extrait-design.md`, construits. Vocabulaire : `CLAUDE.md`.

## Global Constraints

- Aucune nouvelle dépendance npm. Pas de build. JS vanilla. Scripts partagés du navigateur : `public/players.js` (existant) et `public/video-view.js` (nouveau, aussi `require`-able par Node).
- Internet uniquement pour Spotify et YouTube (lecteur, oEmbed, miniature `https://i.ytimg.com/vi/<id>/hqdefault.jpg`) ; une partie sans YouTube ne charge rien de YouTube ; les fichiers vidéo marchent hors ligne.
- Le serveur reste l’unique source de vérité. Pour un passage vidéo, seul le Grand écran qui lit le joue ; `host:ended` est ignoré pour lui ; `screen:ended` est ignoré pour un passage audio, hors étape Jeu, et venant de tout autre Grand écran.
- `performance.now()` reste la première instruction du handler `buzz`.
- Un Z ne rend jamais la lecture audible (règle existante, inchangée).
- Fuite de réponse : le Buzzer ne reçoit rien du morceau ; seul le Grand écran qui lit reçoit `media` (source, ref, Début, Fin) ; aucun Grand écran n’affiche le nom du fichier ni le titre YouTube ; la réponse n’arrive qu’à la révélation (manche buzzer) ou reste la lettre (QCM).
- Sources : `video` (fichier de `videos/`, extensions `mp4 webm m4v mov`, insensible à la casse), `youtube` (identifiant `[A-Za-z0-9_-]{11}`). CSV : écrit `youtube:<id>` ; un fichier vidéo s’écrit par son nom.
- Fichier vidéo : 500 Mo maximum, upload écrit **en flux** sur le disque. Message 413 exact : `Fichier trop gros (500 Mo maximum pour une vidéo).`
- Textes exacts : `Fichier trop gros (500 Mo maximum pour une vidéo).` · `Format vidéo non accepté (mp4, webm, m4v ou mov).` · `Vidéo vide.` · `Cette partie contient des vidéos YouTube : une connexion internet est nécessaire.` · `Aucun Grand écran ouvert` · `Grand écran à l’étape <Étape> : passez à Jeu pour voir la vidéo` · `Le Grand écran attend un clic pour activer la vidéo` · `Cliquez pour activer la vidéo` · `🎬 Morceau n / total` · `🎬 Question n / total` · `Lien YouTube invalide.` · `Vidéo introuvable ou privée.` · `Le propriétaire de cette vidéo interdit sa lecture ailleurs que sur YouTube.` · `Lecture impossible dans ce navigateur.` · `YouTube injoignable : vérifiez la connexion internet.` · boutons `+ Vidéo`, `+ YouTube`, `Ajouter`. Icônes de source : 📁 fichier audio, ♪ Spotify, 🎬 fichier vidéo, ▶ YouTube (Régie : `▶ YouTube`).
- Un nouveau paramètre lu dans `process.env` va dans `.env.example` (`VIDEOS_DIR`).
- Tout CSV, toute partie et tout `scores.json` existants se jouent exactement comme avant.
- Interface, README, commentaires en français (apostrophe `’`, espace avant `:` `?` `!`). Identifiants en anglais. Commits en anglais, Conventional Commits, un changement logique par commit, terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
